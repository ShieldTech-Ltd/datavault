# Selected public GitHub imports

The provider uses GitHub REST API version `2026-03-10` with unauthenticated, fixed `https://api.github.com` requests. Redirects use manual mode and reject all 3xx responses before following or reading them, because workerd does not implement redirect:error. No operator token, browser token, arbitrary URL, redirect, recursive tree walk or download URL is used. Private repositories are unavailable. A future private adapter must obtain user-authorized read-only GitHub App installation or OAuth access, scope it to the account and selected repository, and preserve these bounds. There is no private adapter configured in this version.

Official references inspected before implementation:

- [Repository contents](https://docs.github.com/en/rest/repos/contents): selected files, Base64 encoding, public access without authentication and ref parameter.
- [Git trees](https://docs.github.com/en/rest/git/trees): intentionally not used because imports never crawl a repository.
- [Commits](https://docs.github.com/en/rest/commits/commits#get-a-commit): resolve the selected ref once, then request every selected file at that exact commit.

`POST /api/account/imports/github` accepts exactly `{repository,ref,paths}` and requires the existing owner session, same origin and CSRF token. Select 1 to 10 distinct relative `.md` or `.txt` paths. Repository and ref are bounded and segments are encoded. A job has at most 3 fenced attempts, one inflight job per account and 20 new jobs per rolling 24 hours. Existing account mutation limits also apply. Provider responses total at most 2,000,000 bytes, extracted UTF-8 text at most 500,000 bytes and each whole import has a ten-second deadline. Binary controls, invalid UTF-8 and invalid Base64 fail safely.

Dispatch is real bounded inline processing. No GitHub Queue binding is configured or simulated. The create request persists a queued job, claims a 120-second lease, performs actual fetches and reports review_ready only after a private R2 draft and fenced database transition succeed. `POST /api/account/imports/github/:id/run` is the authenticated bounded local/manual runner and retry seam. A stale lease can be reclaimed; an exhausted third-attempt stale lease is terminalized as failed to release the inflight slot while its tracked draft remains subject to expiry cleanup; a replay of a ready job does no work. Job list and GET expose safe provenance and status only. Session identity contains deployment, so another owner or deployment cannot read, run or cancel a job.

Drafts live under `private-import-drafts/`, separate from immutable collection objects. The R2 object contains repository, exact commit, selected paths, SHA-256 digest and expiry metadata. The database records the object key before writing it so crash leftovers can expire. Owner-only `GET .../:id/draft` returns bounded plain text with no-store; `?download=1` is an explicit private download. Drafts expire after 24 hours. Every import route opportunistically cleans at most 20 expired drafts. `cleanupGithubImports(env)` is available for a future configured maintenance scheduler. No cron is added by this change; without traffic, expired objects remain physically stored until a runner or route performs cleanup, but reads deny them immediately. Cancellation fences the lease and deletes only that private draft. It never touches confirmed collection objects.

The GitHub tab presents public-only support, actual polling state, recoverable job history, cancel, retry, private preview and download. The owner edits content and name, then explicitly hands a File to the existing registration form. Price, disclosure, wallet signature, on-chain confirmation and optional existing revision linking remain required. Importing or previewing does not publish anything. Failed registration leaves the original private draft recoverable until its expiry. Source text and provider tokens are not persisted in browser storage, jobs, notifications, logs or basic account exports. Account export includes at most the 100 most recent safe import metadata records, plus existing account and workspace data.

A read-only acceptance fixture is public repository `ShieldTech-Ltd/datavault`, ref `master`, selected path `docs/receipt-format.md`. Expect the heading `Public receipt` and description of `GET /api/queries/:id/receipt`. The import resolves master to an exact commit shown in provenance. Open GitHub, enter these values, import, preview, review, then use the draft in registration. Stop before registering for private-only acceptance. Publication still requires the normal owner confirmation. This is an existing public DataVault document, not personal data.
