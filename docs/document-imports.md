# Local document import

PDF and DOCX extraction runs inside a disposable browser Web Worker. The dashboard loads the parser chunks only after a file is selected. The original document is never sent to DataVault, an OCR service or a conversion provider. The editable text preview is escaped textarea content. Selecting **Use reviewed text** transfers it into the existing Markdown registration or revision form. The owner still reviews name, price and disclosure and signs the exact UTF8 content hash. Cancellation, component unmount and wallet/network changes terminate pending work and clear the private preview. No plaintext is persisted in localStorage.

Limits are 10 MiB source PDF/DOCX, 200 PDF pages, 30 seconds elapsed extraction time and 2 MiB extracted UTF8 text. Scanned PDFs without selectable text and encrypted PDFs are unsupported. There is no OCR. Check reading order and missing images, headers, footers, tables and embedded content before publication. DOCX supports body paragraphs, heading styles and basic list text. It rejects macros, embedded files, external relationship targets, XML DTD/entity declarations, invalid XML, encrypted ZIP entries, duplicate names, traversal paths, bad CRCs and inconsistent ZIP headers. Unsupported ZIP features, including ZIP64 and multi-disk archives, fail closed.

DOCX uses streamed DEFLATE input in 128-byte compressed increments. Every actual output chunk is counted before retention, with a 10 MiB per-entry limit, 20 MiB aggregate limit and 1000-entry limit. These are actual decompression limits, independent of claimed sizes. All entries are decompressed and checked, including ones not used for text. XML uses the namespace-aware SAX parser without external resolution. PDF.js's core module is loaded into the extraction worker before its API, installing the local message handler so it uses an in-process message loop, not a nested Web Worker. Only text extraction is called, with no page rendering or font loading. Worker network APIs are disabled; asset responses additionally have `connect-src 'none'` and `worker-src 'none'`. Dynamic same-origin module imports remain permitted by `script-src 'self'`.

Markdown/TXT and reviewed uploads accept exactly 2,097,152 UTF8 bytes, plus at most 16,384 multipart envelope bytes. Both browser and server reject invalid UTF8, binary control characters and raw PDF/ZIP inputs. UTF8 BOM bytes are preserved in the content hash. The server accepts only `.md` and `.txt`, never original PDF/DOCX. The immutable R2 key, confirmation flow, receipt versions and selected model context remain unchanged. Retrieval still selects at most four passages of 1600 characters each.

## Dependencies and compatibility

Pinned dependencies: PDF.js `pdfjs-dist` 6.4.299 (Apache-2.0), `fflate` 0.8.3 (MIT), and `saxes` 6.0.0 (ISC). Their license files remain in the installed packages and lockfile pins integrity hashes. Frontend development/build/tests require Node 22.13 or newer. Frontend and combined package CI use Node 22; independent contracts and Worker jobs retain Node 20 pending the separate release runtime upgrade. PDF.js legacy modules include compatibility polyfills and avoid the unsupported `Promise.try` call in the modern module under Node 22. Current Chromium/Firefox are the browser acceptance target; other browsers need separate verification. Upstream currently lists legacy support for Chrome 125+, Firefox ESR and Safari 18+, with caveats. This is not a claim that all combinations have been tested here.

Primary sources inspected 10 October 2026:

- [PDF.js releases](https://github.com/mozilla/pdf.js/releases), including 6.4.299's CPU denial-of-service fix.
- [PDF.js environment support](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions).

## Resource and acceptance boundaries

`cd worker; node scripts/document-size-smoke.mjs` exercises the real bundled retrieval code with an isolated local workerd and local R2 binding. It requires no account, chain, provider or deployment. A 2 MiB run measured 334 ms ingestion and 241 ms retrieval on the inspected Windows machine. Wall-clock measurements do not establish production CPU allowance or peak isolate memory. Hosted 2 MiB ingestion/retrieval on the intended Cloudflare plan remains a release gate, especially on a free plan's CPU allowance. Do not infer production support from local success or a 128 MiB isolate ceiling alone.

Browser fixtures are `frontend/test/fixtures/documents/selectable.pdf` and `selectable.docx`. Both must extract exactly `DataVault fixture paragraph.` with no trailing newline. `no-text.pdf` must show the no-selectable-text message and `encrypted.pdf` the password-protection message. `expected.txt` contains the exact ground truth. PDF fixtures are generated by `frontend/test/document-fixtures.mjs`; the encrypted copy uses a non-secret test password. Root-owned browser acceptance records actual responsive bounds and production worker loading separately.
